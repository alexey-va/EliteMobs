# JSON и Java Serialization: результаты 12 сентября 2026

**Текущий JSON-кодек не даёт общего ускорения.** На заполненных наборах запись в JSON в 2,6 раза медленнее прежнего Java + Base64. На большом наборе чтение тоже медленнее в 1,6 раза. На наборе с 5 квестами среднее время чтения JSON ниже, но повторный замер оставил пересекающиеся интервалы погрешности: надёжного ускорения здесь не установлено.

## Что проверено

- 29 новых проверок: эквивалентность трёх форматов, размеры наборов, постоянные известные значения, типы квестов/целей/наград, прогресс, владельцы, таймеры, обратные ссылки, детерминированность и независимость повторно загруженных объектов.
- Ещё 3 существующих теста JSON-кодека и миграции. Всего **32 теста: 0 ошибок, 0 пропусков**.
- Основной JMH-прогон: **18 комбинаций**, 2 JVM-процесса × 5 замеров по 1 с, перед ними 3 прогрева по 1 с. Все комбинации завершились успешно.
- Дополнительный замер спорного чтения TYPICAL: 2 комбинации, **3 JVM-процесса × 8 замеров по 1 с**, 8 прогревов по 1 с. Только эти случаи повторены.

## Среда и область измерения

Apple M3 Pro, 12 ядер, 36 GiB RAM; macOS 26.5 (25F71), ARM64. OpenJDK 25.0.1+8-27, JMH 1.37, G1, `-Xms512m -Xmx512m`, один рабочий поток. CPU не закреплялся за конкретным ядром; это локальный микробенчмарк на рабочем Mac.

Код плагина: `f9e12080045f62099b6c51a26e0a48b8bbd3e141` (EliteMobs 10.9.0 с нашими DB/JSON изменениями). Реально загружен **Gson 2.11.0 из FreeMinecraftModels-2.12.0.jar**: источник зафиксирован во время запуска, версия проверена через `javap -constants com.google.gson.internal.GsonBuildConfig`. Gradle отдельно разрешает Gson 2.14.0, но он не первый в этом classpath. SHA-256 FMM: `a39e69c633e6c0a250a01712765696bd5b3821410ee39475fcba146e14a0991a`.

Одна операция — преобразование всех четырёх структурированных полей одного игрока: QuestStatus, PlayerQuestCooldowns, DungeonBossLockouts, QuestLockouts. Каждое поле имеет отдельный поток/документ. Это реальные классы EM, заполненные синтетическими значениями; создание данных исключено из времени. SQL, сеть, Bukkit-события и ItemStack-лут не измеряются. Метрика не является временем тика или скоростью сервера.

|---|---:|---:|---:|---:|
| EMPTY | 0 | 0 | 0 | 0 |

TYPICAL — выбранный пример, а не замеренный средний игрок. EMPTY — четыре пустых объекта, не SQL NULL.

## Время, мкс на четыре поля

Среднее ± погрешность JMH для 99,9% доверительного интервала. Последний столбец — отношение средних JSON / Java+Base64: больше 1 означает, что JSON медленнее.

| Набор | Операция | JSON | Java + Base64 | Java без Base64 | JSON / Java+Base64 |
|---|---|---:|---:|---:|---:|
| EMPTY | Запись | 2.46 ± 0.15 | 2.37 ± 1.01 | 2.40 ± 0.29 | 1.04× |
| EMPTY | Чтение | 3.66 ± 0.28 | 11.23 ± 7.68 | 15.38 ± 9.27 | 0.33× |
| TYPICAL | Запись | 98.67 ± 8.61 | 38.16 ± 3.79 | 44.62 ± 6.58 | 2.59× |
| TYPICAL | Чтение | 108.93 ± 15.30 | 149.26 ± 36.73 | 238.71 ± 92.37 | 0.73× |
| HEAVY | Запись | 666.96 ± 84.65 | 253.43 ± 17.60 | 281.47 ± 42.85 | 2.63× |
| HEAVY | Чтение | 813.70 ± 123.75 | 522.17 ± 56.24 | 519.82 ± 60.45 | 1.56× |

## Повторное чтение TYPICAL с длинным прогревом

| Формат | Время, мкс | Средние по отдельным JVM, мкс |
|---|---:|---|
| JSON | 123.81 ± 23.69 | 136.51, 122.19, 112.74 |
| JAVA_BASE64 | 143.21 ± 14.01 | 137.99, 148.67, 142.98 |

По средним время чтения JSON примерно на 14% меньше, но интервалы пересекаются. В итоговый вывод это не включено как доказанное ускорение. Ранний замер с коротким прогревом также сохранён.

В отдельных JVM основного прогона заметен большой разброс: например, Java RAW / EMPTY / чтение дало около 9,6 и 21,2 мкс. По этим данным нельзя утверждать, что Base64 само по себе ускоряет Java; для такого причинного вывода нужен отдельный контролируемый эксперимент. Сравнение с прежним форматом использует именно JAVA_BASE64.

## Выделенная память на операцию

Основной прогон, KiB/op; это все аллокации, а не размер результата или постоянно занятой памяти.

| Набор | Операция | JSON | Java + Base64 | Java RAW |
|---|---|---:|---:|---:|
| TYPICAL | Запись | 241.2 | 115.9 | 70.8 |
| TYPICAL | Чтение | 292.2 | 171.7 | 130.2 |
| HEAVY | Запись | 1631.0 | 553.8 | 305.2 |
| HEAVY | Чтение | 1780.7 | 878.3 | 650.4 |

Нынешний JSON-кодек строит дерево JsonObject/JsonArray, сериализует его в строку и затем кодирует UTF-8. Чтение тоже создаёт дерево и объекты с проверками полей. Эти этапы видны в исходном коде и включены в замер; их отдельный вклад не профилировался. Смена формата сама по себе не гарантирует ускорение.
